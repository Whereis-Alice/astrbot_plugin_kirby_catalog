# OneBot 与 QQ 官方 Bot 数据迁移

**旧端一次采集名称 → 复制插件数据到新服务器 → 管理员关联新旧群并开启自动迁移 → 用户首次抽卡尝试恢复旧收藏。** 不必等所有人重新抽卡，旧收藏本来就在数据目录中。

## 先准备旧数据

1. 旧服务器升级插件后，由 AstrBot 管理员在旧 OneBot 中执行 `采集盟友迁移资料 全部`，逐条查询已有旧收藏账号的 QQ 资料昵称和群名片。只采集当前群用 `采集盟友迁移资料`，也可填写群号。结果分别显示群数、账号记录数、不同 QQ 数、完整／仅昵称／失败数量、实际接口调用次数及写入数；收藏、今日盟友与次数保持不变。只更新已有收藏账号，不为未抽过卡的成员创建空图鉴。
2. 停用旧端插件后，将它的整个数据目录复制到新服务器相同位置。默认是 AstrBot 数据目录中的 `plugin_data/astrbot_plugin_kirby_catalog/`，包含素材、收藏、抽取次数和身份关联。也可以使用 WebUI 的 ZIP 备份按钮搬运这些文件。
3. 新服务器启用插件，由管理员关联新旧群，再开启下文的自动迁移。两个独立服务器的文件不会实时同步，复制之后旧端继续抽到的新收藏不会自动进入新服务器。

旧版本只有用于显示的 `nickname`，可能是群名片，自动迁移不会把它冒充 QQ 资料昵称。v4.12.0 调用的是群成员列表，未逐人请求跳过缓存；v4.12.1 改为下述逐条查询，可升级后重新执行同一指令。

- 旧文件只提供目标群号和 QQ 号；每条群／账号记录调用 `get_group_member_info(group_id, user_id, no_cache=true)`，每个不同 QQ 本轮调用一次 `get_stranger_info(user_id, no_cache=true)`，跨群复用本轮 QQ 资料结果。API 并发最多 2，每次 15 秒超时。
- 资料昵称优先使用 QQ 资料接口的 `nickname`；此接口失败时，可采用本轮群成员接口的 `nickname`，报告注明来源与错误。群名片取群成员接口的 `card`，空名片也算有效返回。
- 仅取得资料昵称时标为“仅取得资料昵称”，没有取得群名片就保留旧名片并标记为旧值。两种接口都没取得昵称时标为失败，不用旧名称冒充本轮查询成功，也不据此推断已离群。协议端是否真正向 QQ 网络刷新取决于其对 `no_cache` 的实现。
- 发送 `迁移采集报告` 查看未完成项，`迁移采集报告 全部` 查看全部。每项包含群号、QQ 号、旧显示名、接口取得的昵称／群名片与失败原因；群中仅显示当前群，管理员私聊可查所有群。完整 JSON 报告按采集 ID 保存到插件数据目录 `identity-capture/`，`latest.json` 是最近一次报告，重载后可继续查看。中断时保留已写入结果与未完成名单，可重新采集。

原收藏始终保留，无法查询资料的用户仍可用专属码迁移。正常抽卡也会继续更新两种名称，包括达到每日上限的命令。

WebUI 的 ZIP 备份包含已采集的身份名称。需要在新服务器继续查看采集报告时，也请复制 `identity-capture/` 目录；复制整个插件数据目录会一并带走报告。

## 管理员先关联新旧群

在 AstrBot 管理员私聊中发送：

```text
盟友群绑定码 旧群号
```

再由 AstrBot 管理员在目标官方群发送：

```text
绑定盟友群 收到的码
```

群图鉴和排行榜会延续旧群记录。新端已经抽过的官方成员记录迁入同一群的独立身份空间；群绑定本身不按名字认领个人收藏。

如需同时迁移 Bot 自己的收藏，签发时指定旧数据中的 Bot ID，例如 `盟友群绑定码 123456 bot_987654`。人工配置 `bot_draw_identity` 继续优先。

## 抽卡时自动匹配

在“QQ 官方 Bot 富文本与按钮”中开启 **按唯一资料昵称自动迁移旧收藏**。默认关闭，因为名称可以被修改，唯一匹配也不能证明账号归属。

- 只在管理员已关联的新旧群中运行；不在全部群里搜索同名用户。
- 官方消息必须实际提供 `author.username`，与旧端记录的 **资料昵称** 精确相等；群名片、模糊相似名字和 OpenID 不参与匹配。
- 只有一个旧 QQ 账号匹配，且没有被其他官方身份关联时，抽卡前生成并消费内部一次性码，用户不会看到码，也不用额外输入。
- 匹配成功后保存长期关联，之后每次抽卡直接用旧数据；不会反复合并或再次增加次数。
- 字段缺失、同名或已被关联时跳过，用户正常使用新身份抽卡。稍后用专属码仍能合并新旧收藏。
- 首次成功显示“已恢复你的旧收藏”；后续抽卡直接读同一份数据。未恢复时说明名称缺失、旧名称未采集、名称未找到、同名、已被关联或群对应关系未设置的具体原因，并提供专属码入口。同一原因只提示一次；原因发生变化时再次提示。

AstrBot 4.29.4 的官方群解析器读取 `author.username`，这是可选字段，不保证每条群消息都有。官方单聊也没有保证提供名称；不能把 `event.get_sender_name()` 的显示值当作必然真实的资料昵称。因此此功能只能在实际收到该字段时自动迁移，不能保证所有用户都能通过名称完成迁移。群聊／单聊不同的 OpenID 无法仅凭相同显示名称证明是同一人。

## 专属码验证

这条路径不依赖昵称，建议同名用户、改过名的用户和未提供名称的官方账号使用。

1. 用户在目标官方群或官方单聊发送 `盟友身份`，复制 24 位“目标身份码”。身份码不是登录凭据。
2. 私聊旧 OneBot：`盟友绑定码 旧群号 目标身份码`。旧账号只能为自己的 QQ 号取码。
3. 回到获取身份码的原会话：`绑定盟友 绑定码`。

绑定码 20 分钟有效、仅指定的官方身份能消费；泄露到其他用户或会话也不能被认领。重领会撤销同一旧账号此前未用的码。同一身份重复提交已经完成的码不会再次合并。

旧 Bot 已下线时，新服务器先导入旧备份，管理员核验用户归属后私聊签发：`管理员盟友绑定码 旧群号 旧QQ号 目标身份码`。用户再执行第 3 步。

只有个人绑定时，可以查看自己的旧收藏；群图鉴、排行榜和查询其他成员仍只显示本会话的数据。官方群绑定到旧群后，成员不能再用另一个旧群的码覆盖它。

## 合并与恢复规则

- 收藏按素材文件名去重，保留最早解锁日期；今日角色优先取日期较新的有效素材，同日保留旧记录，连续未出新计数取较高值。
- 新旧记录每天的已用次数相加；额外机会取较高值，避免复制管理员额度。两端在同一实例中使用同一份记录和次数。
- 合并后移除临时身份中的旧记录和计数，避免排行榜双计；绑定和抽卡共用锁。
- 每次合并先保存快照到插件数据目录 `identity-backups/`，保留最近 20 份。写入中断由 `identity-links-transaction.json` 在启动前回滚；恢复失败时不会继续操作部分迁移数据。
- 快照保存了合并前涉及的群文件、次数和绑定关系。需要人工回退时先停用插件并保存当前整包，核对快照后恢复所需记录；不要在后续已有新抽卡时无差别覆盖整个旧快照。
- 配置整包包含 `config/identity_links.json`；未使用的短期绑定码不导出。绑定合并导入有冲突时，会在写入群数据前拒绝。

绑定使用 QQ AppID 的稳定身份。同一官方 Bot 换服务器、重新添加 AstrBot 平台配置后仍可继续关联；换一个 AppID 会得到不同 OpenID，需重新验证。导入完成后重载插件即可，已经建立的绑定无需再操作。平台认证仍使用 AstrBot 自己的配置。
