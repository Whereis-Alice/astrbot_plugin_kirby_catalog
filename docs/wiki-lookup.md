# 百科查询

[← 返回 README](../README.md)

插件提供三个彼此独立的卡比资料来源。查询失败只会影响当前百科回复，不会影响抽取和图鉴数据。

## 来源区别

| 命令 | 来源 | 适合查询 |
| --- | --- | --- |
| `卡比百科` | [WiKirby](https://wikirby.com/wiki/Kirby_Wiki) | 结构化资料、简介、出现信息、趣闻和页面记录的多语言名称 |
| `卡比F` | [Kirby Wiki \| Fandom](https://kirby.fandom.com/wiki/Kirby_Wiki) | 作品经历、外观、性格、信息框、相关语录、招式与按章节读取的长篇正文 |
| `卡比真格` | [星のカービィ 真 ボスバトル攻略Wiki](https://seesaawiki.jp/kirby_shinkaku/) | 真格斗、Boss 行动规律、攻略法、防御力变化、能力实机记录与日英用语 |

> [!CAUTION]
> `卡比F名称` 返回的是不同语言 Fandom 社区的页面标题，只能作为检索线索，不等同于任天堂官方译名。需要核对官方译名时，请优先使用 `卡比百科名称`，并以任天堂正式发布内容为最终依据。

## WiKirby 命令

| 命令 | 作用 |
| --- | --- |
| `卡比百科 [查询词]` | 查询页面简介、资料、多语言名称、首图和来源链接 |
| `卡比百科名称 [查询词]` | 只返回页面记录的多语言名称；别名：`卡比百科名`、`卡比百科译名` |

WiKirby 支持 `88`、`#88`、`编号 88` 和 `序号 88`。默认编号沿用盟友图鉴编号，也可在 WebUI 的“百科序号”页面单独改号、修改查询目标或停用，不会改变盟友图鉴排序。

也可以引用 Bot 发出的盟友消息执行 `卡比百科`、`卡比百科名称`、`卡比百科文本`、`卡比百科卡片` 或 `卡比百科文档`。插件会优先使用图鉴记录中的英文 `page_title`；没有编号时再从角色名的英文括号或素材名中提取查询词，不会把开头的作品名称当成角色。

## Kirby Fandom 命令

| 命令 | 作用 |
| --- | --- |
| `卡比F [页面名]` | 查询简介、信息框、分类、正文栏目、相关语录、招式表、首图和来源 |
| `卡比F章节 [页面名]` | 列出当前页面可查询的栏目 |
| `卡比F [页面名] \| [栏目名]` | 只读取指定栏目；父栏目会自动汇总其子栏目 |
| `卡比F名称 [页面名]` | 查询日文名和各语言 Fandom 社区页面标题 |

兼容别名：`卡比Fandom`、`卡比Fandom章节`、`卡比Fandom名称` 和 `卡比社区百科`。

Kirby Fandom 同样支持 `88`、`#88`、`编号 88` 和 `序号 88`。默认编号沿用盟友图鉴编号，但它拥有自己的 WebUI 覆盖层，可以与 WiKirby 使用不同查询目标或不同序号。

`卡比F`、`卡比F文本`、`卡比F卡片` 和 `卡比F文档` 都支持引用盟友消息查询，并与 WiKirby 命令共用“优先英文角色名、忽略作品前缀”的解析规则。

## 真格攻略 Wiki 命令

真格攻略 Wiki 是日文 Seesaa Wiki，专注于真 Boss Battle 与相关 Boss、能力的实机攻略。插件以原站公开“页面一覧”为基准建立了全部 301 页的三语名称索引：中文优先采用已核验的官方简体中文名称，无法确认官译时明确标注为“本项目自译”；英文与日文原名始终保留。

| 命令 | 作用 |
| --- | --- |
| `卡比真格 [页面名]` | 查询 Boss、能力或攻略页面；完整中文、英文、日文名称都可直接检索 |
| `卡比真格章节 [页面名]` | 列出页面可查询的日文攻略栏目 |
| `卡比真格 [页面名] \| [日文栏目名]` | 只读取指定栏目，例如行动规律或攻略法 |
| `卡比真格名称 [名称]` | 优先查询 301 页中英日页面名称；无结果时再查询原站日英术语表 |
| `卡比真格速查图` | 发送完整的中文 / 日文页面名称速查图；编号与文档命令共用 |
| `卡比真格文档 [编号]` | 按速查图编号直达对应页面并生成完整 HTML 文档，例如 `卡比真格文档 88` |

兼容别名：`卡比真格斗`、`卡比真格Wiki`、`真格攻略`、`真格Wiki`，以及它们的 `名称`、`名`、`章节`、`速查`、`目录`后缀。命令中的 `Wiki` 不区分大小写。

速查图中的编号支持 `88`、`#88`、`编号 88` 和 `序号 88`。编号按“作品 -> 原站栏目 -> 原站菜单顺序”排列，同一作品会先完成综合资料、复制能力/可操作角色、首领攻略等栏目，再进入下一部作品；它不是盟友图鉴编号，两套编号互不影响。

与另外两部百科一样，引用 Bot 发出的盟友消息后直接发送 `卡比真格`、`卡比真格文本`、`卡比真格卡片` 或 `卡比真格文档`，插件会优先使用该盟友的英文 `page_title` 查询；无法唯一定位页面时会列出中英日候选，避免误把不同作品的 Boss 版本混在一起。候选列表默认按合并转发发送，每个候选独占一个节点；可通过“真格多候选页面回复形式”切回普通消息。

同一个短名称可能同时存在于 Wii、三重豪华版、机器人星球、新星同盟、探索发现或 Wii 豪华版页面。此时插件会列出完整中文、英文、日文候选，用户选择带作品名的完整标题即可直达。公开索引可直接查阅：

- [Markdown 分类名称表](../resources/shinkaku_page_names.md)
- [CSV 名称表](../resources/shinkaku_page_names.csv)
- [JSON 运行时索引](../resources/shinkaku_page_names.json)

群内发送 `卡比真格速查` 或 `卡比真格速查图` 会直接发送插件仓库内预先生成的 PNG 速查表，不需要服务器在首次查询时重新绘制。固定高清图把 301 个页面排成一张 `2160px` 宽的五列总览图：作品与栏目标题横跨整行，每项显示 `#目录编号`、简体中文和日文页面名，组内不重复显示作品后缀。中文约 `30px`，日文约 `23px` 并加粗；完整图为 `2160×9704`、`20.96MP`、约 `2.00MiB`。速查资源使用独立的原图发送路径，不套用百科卡片的缩放阈值，也不会转成 JPEG。关闭“真格速查优先使用内置高清图”后，才会恢复动态单张或分页渲染设置。

名称表分别保留中文和英文来源状态：`官方译名`、`沿用系列官译`、`本项目自译`、`原文保留`。分类目录按作品年代和原站栏目排列，同时保留原始页面列表序号，便于以后核对新增、删除或改名页面。

真格页面中的能力、评价、实机记录等 HTML 表格不会再压成一段普通文字。选择卡片或文档回复时，插件会保留表头、完整行和页面原有的全部图片：既包括 Seesaa 自带图床上的能力图标，也包括「記録集」这类页面托管在 imgur、Gyazo 等站外图床的实机记录截图。图片会按真实像素尺寸分成“图标”和“实机截图”两类分别渲染——图标保持行内小图，截图放大到可读尺寸并带圆角和投影；组合记录按“图标 × 图标”显示，纯图标单元格不会出现多余横线，原站编辑列也会自动排除。主模块、折叠子模块和表格按网页原始顺序排列，表格始终留在所属模块内。表格里的视频、图片和资料链接会附着在对应名称上，文档中可直接点击，不会再在正文和页尾重复堆放。开启“使用 LLM 将真格攻略日文翻译成简体中文”后，会翻译栏目名、表头和自然语言单元格，同时保留 `SS`、`A`、数字、实机时间和 `--` 等原始数据。表格太长时按完整行分页，后续卡片会重复表头。

纯文字回复（`卡比真格文本`、合并转发）无法内嵌图片，只有截图没有文字的单元格会输出 `图片：<直链>`，多张用 `、` 分隔，方便直接点开查看成绩截图。

页面第一个栏目之前的能力说明也会完整读取，并作为页面简介显示在文字、卡片和 HTML 文档中。原网页的换行、粗体和红色重点词会保留为安全的本地排版；能力图标继续作为页面首图使用，不会在正文重复出现。只有页面确实没有这段导语时，插件才使用栏目名称生成简短概览。

`详细数据` 一类逐招式资料会保留网页中的粗体、斜体、层级列表和字段顺序。卡片按完整招式组成最多两列的资料单元；同一招式的指令、发生、动作、硬直、无敌和修正数据不会被拆到另一列或另一页。HTML 文档在电脑端使用同样的双列布局，手机端自动改为单列。

## 按本次查询指定发送形式

三个百科都可以直接在命令名后加“文本”“卡片”或“文档”。这只覆盖当前一次查询，不会修改插件配置中的默认回复形式。

| 来源 | 文字版 | 卡片版 | 文档版 |
| --- | --- | --- | --- |
| WiKirby | `卡比百科文本 Fight` | `卡比百科卡片 Fight` | `卡比百科文档 Fight` |
| Kirby Fandom | `卡比F文本 Fight` | `卡比F卡片 Fight` | `卡比F文档 Fight` |
| 真格攻略 Wiki | `卡比真格文本 ファイター(RBP)` | `卡比真格卡片 ファイター(RBP)` | `卡比真格文档 ファイター(RBP)` |

查询词也可以换成对应百科序号，例如 `卡比百科文档 #1202`、`卡比F卡片 157`、`卡比真格文本 序号 109`。三套序号互相独立；若管理员在 WebUI 中停用或改号，旧数字不会再自动退回盟友图鉴编号。

- **文本版**：使用 `【栏目】` 与 `◆ 子栏目` 重新编排正文和表格，避免 QQ 纯文本挤成无法阅读的一大段。默认按栏目拆成合并转发；关闭 `wiki_text_command_use_forward` 后改发普通文字消息。
- **卡片版**：使用当前百科设置的模板生成图片。模块按来源页面顺序纵向排列，不再强制压成三列；短页面保持单张，真正过长时按完整栏目、语录、招式或表格行分页。
- **文档版**：生成一个自包含的响应式 HTML 文件。它会读取当前页面全部可解析栏目，不受对应百科“显示详细资料”开关影响，并保留模块顺序、子标题、文字强调、表格、语录、招式、首图、真格攻略多图标、单元格原始链接、来源链接和未归属媒体。相关媒体会按来源紧凑分组，已附着到表格名称的链接不会重复列出。手机端技能资料自动改为单列，宽表格只在表格区域横向滚动。

兼容的长命令别名同样支持发送形式后缀，例如 `卡比Fandom文档`、`真格Wiki卡片` 和 `wikirby文本`。

## 回复形式和卡片

WiKirby、Kirby Fandom 与真格攻略 Wiki 都支持以下回复形式：

- 普通消息；
- 合并转发；
- 仅百科卡片；
- 百科文字 + 卡片；
- 文字 + 卡片合并转发；
- 百科文档。

百科卡片由 AstrBot T2I 服务渲染。默认使用 `1600px` 逻辑视口、`高清` 设备像素截图和质量 `92` 的 JPEG，在文字清晰度、文件大小和 QQ 上传稳定性之间取平衡；也可切换为 PNG、标准或超清。

普通页面仍只生成一张卡片。卡片不再显示“资料速览”，也不会为了统一三列而压缩字号：长模块使用整行宽度，较短的子模块才会使用双列；四组深色栏目标题帮助区分相邻模块。只有内容预计过长，或渲染后的宽高、总像素、文件大小超过安全阈值时，插件才会自动分页。分页按简介续篇、完整资料模块、语录条目、完整招式和表格行拆分；每页重复页码与来源，招式表和真格攻略表的续页会保留表头，同一招式不会跨页拆开。默认安全阈值为宽 `2160px`、高 `8000px`、`18MP` 和 `8MiB`，这些是针对协议端与 QQNT 的保守兜底，不是 QQ 官方公布的硬限制。

使用合并转发时，插件会按段落把长文字拆成多个节点，图片或百科卡片放在独立节点。单个文字节点默认最多 3000 个字符，单条合并转发默认最多 20 个节点；超出后会继续发送下一条合并转发，正文不会被截断。这两个限制用于规避协议端与 QQ 对超大转发载荷的不稳定处理，不是百科内容长度限制。

Kirby Fandom 的特殊栏目会保留网页结构和原始位置：`Related Quotes` 中每条语录独立显示正文、出处和作品；`Techniques` 按作品及 Type A / Type B 分组，以“招式、操作、说明、伤害”四列表格显示，并留在原页面对应正文之间。网页里的手柄按钮图片会转换为可读操作文字，例如 `Pro 手柄：冲刺 + B`、`Joy-Con：下方向键`。所有子标题、语录、招式分组、操作说明和表格行都会完整保留。

内置模板：

| 模板 | 配色与版式 |
| --- | --- |
| `梦之泉` | 水蓝、薄荷绿、梦境紫与星光金；WiKirby 默认模板 |
| `卡比粉彩` | 卡比粉、天蓝、淡紫与奶油黄；Fandom 默认模板 |
| `瓦豆鲁迪` | 浅杏橙、奶油黄、草绿与青色；观察笔记式左侧首图 |
| `星际档案` | 银蓝、浅靛蓝、青色与淡金；克制的资料档案排版 |

卡片渲染失败时会自动回退到文字回复，不会丢失百科内容。关闭 `wiki_card_auto_paginate` 可以恢复单张长图，但超长页面更容易触发 QQNT 的 `rich media transfer failed`。

## LLM 工具

插件注册以下工具，AstrBot 的 LLM 可以主动调用：

| 工具名 | 能力 |
| --- | --- |
| `kirby_catalog_lookup_wikirby` | 查询 WiKirby 页面资料 |
| `kirby_catalog_lookup_official_names` | 查询 WiKirby 多语言名称 |
| `kirby_catalog_lookup_fandom` | 查询 Kirby Fandom 页面资料或指定章节 |
| `kirby_catalog_lookup_fandom_names` | 查询 Fandom 跨语言社区页面名称 |
| `kirby_catalog_lookup_shinkaku` | 使用中文、英文、日文名称或速查图编号查询真格攻略 Wiki 页面和指定日文攻略栏目 |
| `kirby_catalog_lookup_shinkaku_terms` | 查询全部 301 页的中英日名称；无页面结果时回退原站日英术语表 |
| `kirby_catalog_draw_bot_ally` | 使用 Bot 独立身份抽取当前群当天盟友，立即发送文字和素材图片，并让视觉 LLM 查看同图后回复 |
| `kirby_catalog_view_bot_gallery` | 查看 Bot 在当前群的个人盟友图鉴，立即发送图鉴页，并让视觉 LLM 查看同页后回复 |

前六个百科工具只读，不会发送群消息或修改图鉴；真格攻略正文会保留日文，避免工具调用中再次嵌套 LLM 翻译。`kirby_catalog_draw_bot_ally` 会写入 Bot 自己在当前群的当天盟友和解锁记录，但不会占用提问者的次数或修改群友数据。`kirby_catalog_view_bot_gallery` 只读取这份当前群 Bot 图鉴，不会消耗次数或解锁新条目。两个 Bot 工具都会主动向当前群发送结果；默认还会把同一份轻量化图片交给视觉 LLM，使爱丽丝能看图后自然回应，但不会重复发送相同内容。三个百科查询工具默认还会把页面首图和真格攻略表格里的实机记录截图作为视觉输入一起交给模型，让模型能读出写在截图里的成绩数据，可通过 `wiki_llm_vision_enabled` 关闭。
