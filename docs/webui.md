# WebUI 图鉴管理台

[← 返回 README](../README.md)

插件提供 AstrBot Dashboard 原生管理 Page。更新并重载插件后，在 Dashboard 的插件详情中打开“星之卡比图鉴管理台”即可使用，不需要另开端口或部署独立前端。管理台共八个页面，界面为悬浮玻璃顶栏加胶囊导航，概览页是一屏四段的仪表盘，全部资源内联、零外部请求。

> [!IMPORTANT]
> 完整管理台依赖 AstrBot `v4.26.8+` 的插件 Page 和 Web API。插件声明兼容 `>=4.22.2,<5`；这个最低版本同时确保 Bot 抽取工具可以把素材图作为原生视觉工具结果交给 LLM。低于 `v4.26.8` 时，群聊命令仍可用，但不显示这套管理页面。

## 管理范围

| 页面 | 可执行操作 |
| --- | --- |
| 概览 | 查看图鉴总数、缺图/缺简介、群组与成员规模、今日抽取、作品分布和最近操作 |
| 素材库 | 按编号、名称、英文名或作品搜索；按作品、类型和资料状态筛选；新增素材、换图、改名、修改首次登场作品和简介 |
| 名称库 | 管理角色、形态、能力、作品、地点和机制的中英文日名称、别名、优先级与匹配开关；查看缺失语言和冲突；导入导出 JSON/CSV；恢复内置版本 |
| 百科序号 | 分别管理 WiKirby、Kirby Fandom 和真格攻略 Wiki 的快速查询序号、实际查询目标和启用状态；筛选冲突与管理员修改；恢复内置值 |
| 群数据 | 查看全部群和成员；编辑昵称、当前盟友、当前日期、连续未解锁次数、今日已用次数和额外次数；增删个人解锁、重置群今日次数或删除成员记录 |
| 回收站 | 查看已删除条目，并恢复固定编号、素材、简介覆盖和仍可恢复的群成员引用 |
| 操作记录 | 查看 Dashboard 中的素材和群数据管理记录，包含操作者、时间、对象和变更摘要 |
| 数据备份 | 导出七类数据与素材图片、上传备份文件预检、确认后写入；换服务器时按推荐顺序整机迁移 |

名称或首次登场作品发生变化时，管理台会同步重命名素材文件，并更新所有群的当前盟友与历史解锁引用。换图只替换图片内容，不改变固定编号和用户解锁。新增条目使用新的固定编号；回收站中的旧编号不会被后续新增素材占用。

## 数据备份与导入导出

「数据备份」页可以把管理台里的数据导出成文件，也可以从备份文件恢复到当前这台机器。七类数据彼此独立，既能只导一类，也能整机迁移。

| 数据 | 格式 | 导入方式 | 内容 |
| --- | --- | --- | --- |
| 图鉴资料 | JSON / CSV | 合并 | 角色名称、首次登场作品与简介；导入只更新已存在的素材，不会凭空新建条目 |
| 名称库 | JSON / CSV | 合并 / 整体替换 | 中日英对照译名、别名、优先级与匹配开关 |
| 百科序号 | JSON / CSV | 合并 / 整体替换 | 三个百科站点的记录集序号与实际查询目标 |
| 群组进度 | JSON / CSV | 合并 / 整体替换 | 每个群里成员的当前盟友与解锁记录，可只导单个群 |
| 操作记录 | JSON / CSV | 仅导出 | 最近 500 条后台操作日志 |
| 配置整包 | ZIP | 合并 / 整体替换 | `catalog.json`、`config/` 与 `webui/` 的完整快照 |
| 素材图片 | ZIP | 合并 | `img/allies/` 下的全部图片，按分卷下载 |

前五类还可以选导出范围：「全部数据」导出内置值与管理员改动合并后的结果，「仅自定义」只导出管理员实际改过的部分，适合把自己的修改搬到另一台机器而不带上内置数据。CSV 一律带 BOM 并用 CRLF 换行，Excel 直接双击就能正确显示中文。

导入分两个阶段。上传的文件先写进数据目录下的 `webui/transfer/` 暂存区并做完整预检，页面上会列出总计 / 新增 / 更新 / 不变 / 跳过的条数、最多 8 条变更样例和冲突警告，点「确认导入」之后才真正落盘。预检不通过或者没点确认，插件数据一行都不会变。暂存文件 6 小时后自动清理，也可以随时「丢弃」。整体替换只影响管理员的自定义层，内置名称库和内置百科序号不会被清空。

换服务器时按这个顺序做：

1. 旧机器：先把「素材图片」的每一卷都下载下来，再导出「配置整包」；
2. 新机器：先逐卷导入素材图片，再导入配置整包。

反过来先导入配置整包的话，索引会先落盘而图片还没到位，管理台会有一段时间显示大量「缺少图片」。

素材图片是唯一可能超过单文件上限的部分（一份完整图鉴的图片通常有几百 MB），所以按每卷约 64 MB 切分，页面上直接选第几卷下载；导出全程按 256 KB 分块流式写出，不会把整个压缩包读进内存。文本类导出实测在 1.5 MB 到 4 MB 之间，可以直接下载。

上限如下：单个文本文件 16 MB，压缩包 96 MB，压缩包内单张图片 12 MB，压缩包最多 5000 个成员、解压后总计 512 MB，图鉴资料一次最多接受 600 条变更，暂存区总量 512 MB。压缩包成员名会逐个校验，绝对路径、盘符前缀和任何 `..` 路径段都会被拒绝；导入的图片还要通过 Pillow 的完整性校验才会写盘。

## 皮肤与响应式布局

右上角提供四款皮肤：

- 跟随（`auto`）：随 AstrBot Dashboard 当前明暗外观自动在梦之泉与星光夜之间切换；
- 梦之泉（`dreamland`）：粉色日间皮肤，卡比配色的默认浅色方案；
- 星光夜（`starlight`）：深空夜间皮肤，适合长时间整理大量素材；
- 元骑士（`metaknight`）：冷蓝紫皮肤，偏低饱和的暗色方案。

旧主题名会自动迁移：`kirby` 和 `light` 映射为梦之泉，`dark` 映射为星光夜，`meta` 映射为元骑士。已保存的偏好不会丢失，不需要任何手动处理。皮肤写在 `<html data-kirby-skin>` 而不是 `data-theme`，因为 AstrBot 宿主会重写后者。

桌面端使用高密度表格与右侧编辑抽屉，便于连续处理数百或上千项素材；长列表采用有界渲染，手机端会改为纵向列表和全屏编辑面板。抽屉带焦点陷阱，表格行支持键盘 Enter / Space 打开编辑。

视口宽度在 `1361px` 以上时八个页面全部一屏满铺、页面本身不滚动，长列表在各自的分区内滚动，打开管理台即可看到整页的全部功能；`1366×900` 这类小尺寸笔记本屏也仍是一屏。`1360px` 及以下自动回落为普通文档流，打印时同样。数据表行高统一为 `66px`（素材库带缩略图，为 `67px`）；窗口窄于表格下限时，表格区域可以左右滚动查看被挤出的列。

## 前端结构

管理台前端由 26 个原生 ES module 组成，没有构建步骤和打包产物：

- `app.js`：只负责引导；
- `js/core/`：dom、format、labels、state、bridge、summary、theme、router、icons、icon-glyphs；
- `js/ui/`：toast、confirm、drawer、widgets、pagination、combo、upload；
- `js/views/`：概览、素材库、名称库、百科序号、群数据、回收站、操作记录、数据备份八个视图；
- `styles/`：`tokens.css`、`base.css`、`components.css`、`views.css`。

图标为 102 个内联 SVG，不随插件打包第三方图标脚本，首屏没有任何外部图标请求，也不依赖 CDN。插件 logo 的矢量版也内联在顶栏里，同样不产生额外请求。

样式分层的职责是：`tokens.css` 只放变量（三款皮肤各自的配色、渐变、光斑、噪点与玻璃背板），`base.css` 放骨架与顶栏，`components.css` 放可复用组件（指标卡、表格、徽章、抽屉、弹层、表单），`views.css` 放八个视图各自的版式与一屏满铺规则。

## 权限与数据安全

- 管理 API 继承 AstrBot Dashboard 的登录鉴权，不提供匿名公开入口；不要在反向代理中绕过 Dashboard 身份验证单独暴露 `/api/plug/astrbot_plugin_kirby_catalog/`。
- WebUI 写操作与群内抽取共用同一把锁，避免管理员修改资料时恰好发生抽取而互相覆盖。
- 素材名称、首次登场作品和简介作为一次事务保存；成员资料与今日两类计数也会一起提交。任一磁盘写入失败时会自动恢复修改前状态。
- 删除素材只会移入回收站，不提供永久删除按钮。恢复会尽可能还原删除时受影响的当前盟友和解锁记录。
- 大批量整理前先用「数据备份」页导出一份，或直接备份整个插件数据目录；WebUI 回收站不能代替备份。
- 导入走两阶段：上传只写进插件数据目录下的临时暂存区并做预检，点「确认导入」才真正落盘；暂存文件 6 小时后自动清理。
